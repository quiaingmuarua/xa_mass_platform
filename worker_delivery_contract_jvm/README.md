# XA Mass Worker Delivery Contract JVM

Status: repository-local Java 11 protocol boundary.

This module contains the transport-neutral Worker Delivery DTOs, strict
deterministic codec, outcome classification, and `Jsons` facade shared by
`kernel_jvm`, `server_jvm`, `transport/netty-adapter`, and
`transport/core`. Concrete Worker and Android network modules consume it
through that Core boundary.

## Protocol

Worker routing uses `workerId` outside the message. The two asymmetric message
contracts are:

```text
WorkerCommand(
  messageId,
  src,
  dst,
  messageType,
  executeBeforeMillis,
  payload,
  forward
)

WorkerResult(
  messageId,
  dst,
  messageType,
  outcomeCode,
  payload,
  forward
)
```

`src` and `dst` use the explicit wire enum:

```text
TASK | SYSTEM | ADAPTER | WORKER
```

A command source is `TASK`, `SYSTEM`, or `ADAPTER`; its destination is always
`WORKER`. A result destination is the original command source. The current
production path is `TASK -> WORKER -> TASK`.

`messageId` is a canonical UUID generated by the command source. A Worker
copies it into the result for correlation. It is not a TaskItem identity,
idempotency key, result truth, or lease fence.

For a Task command:

- `messageType` is the TaskItem `eventCode`;
- `payload` is the encoded TaskItem payload;
- `forward` is opaque Result Routing context;
- `executeBeforeMillis` is checked before execution starts.

The Worker copies `messageId`, `messageType`, and `forward` into its result,
sets `dst=TASK`, and supplies `outcomeCode` plus its opaque payload.

Long-lived connections first send the separate bind DTO:

```json
{"workerId":"worker-1"}
```

After bind, WebSocket and line Socket transports exchange direct
`WorkerCommand` and `WorkerResult` JSON. There is no outer connection-message
envelope and no transport-specific command/result DTO.

## JSON Boundary

`Jsons` exposes only JDK JSON values:

```text
Map / List / String / Boolean / Number / null
```

The private JSON engine is fixed inside this module. Gson types, arbitrary
POJO reflection, runtime engine selection, and fallback decoding are not part
of the public contract. Protocol codecs reject missing fields, extra fields,
wrong types, invalid endpoint directions, non-canonical UUIDs, invalid
outcome codes, and non-positive deadlines.

This module has no Spring, Redis, Server, Kernel, scheduling, connection,
lifecycle, or business-handler dependency. Server HTTP DTOs and Redis queue
suffixes remain owner-local.
