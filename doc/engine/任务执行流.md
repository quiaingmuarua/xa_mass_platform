## §1 当前实现（已验证）

### 1.1 任务创建

入口：`POST /status/api/tasks` → `TaskApiController.createTask()` → `TaskManager.createTask(dto)`

```
TaskCreateRequestDto
  ├── taskName, project, countryCode, textContent, userId
  ├── targetList: ["target-001", "target-002", ...]   ← 直接传目标列表
  └── batchSize: 1

TaskManager.createTask():
  1. 生成 UUID 作为 tid
  2. 构建 Task 对象，status = NEW
  3. taskStorage.saveTask(task)
  4. 遍历 targetList，每个 target 生成一个 TaskMsg(msgId, tid, target)
     └─ 每个 TaskMsg 独立 UUID，绑定 taskId，target 字段存目标标识
  5. 返回 Task 对象
```

**重要约束**：
- `targetList` 为 null 时安全（不生成 TaskMsg，不抛 NPE）
- `targetList` 和 `targetJsonList` 均支持，分别累加到 `taskInitNumber`

### 1.2 任务状态机

```
NEW
 ├──approveTask()──► READY
 │                     ├──pauseTask()──► PAUSED ──resumeTask()──► READY
 │                     └──cancelTask()──► TERMINAL
 ├──rejectTask()──► BLOCKED ──approveTask()──► READY
 └──cancelTask()──► TERMINAL
```

| 方法 | 允许的初始状态 | 目标状态 |
|------|--------------|---------|
| `approveTask` | NEW, BLOCKED | READY |
| `rejectTask` | NEW | BLOCKED |
| `pauseTask` | READY | PAUSED |
| `resumeTask` | PAUSED | READY |
| `cancelTask` | 任意非 TERMINAL | TERMINAL |
| `deleteTask` | **NEW, TERMINAL 仅** | （物理删除） |

### 1.3 设备分配流程（MockMode 下）

仅在 `MassEngine` 以 `mockMode=true` 启动时激活：

```
Task 进入 READY 状态
  └── TaskAssignWorker（后台线程）拉取任务
        └── TaskDeviceAssignListener.onTaskAssign(task)
              ├── 计算所需设备数 = ceil(taskInitNumber / batchSize)
              ├── DeviceManager.getDevicesByCountry(task.taskCountry)
              ├── 用 RuleManager 对每台设备做规则评估
              │     └── 全部规则通过 + tryLockDevice() 成功 → 设备入选
              └── SimpleTaskMsgAssignListener.onMsgAssign(task, matchedDevices)
                    └── 按设备数平均分配 TaskMsg 槽位
                          ├── 构建 TaskMsg(msgId, tid, deviceId)，绑定 tokenId、batchId
                          └── pushQueue（当前只在内存中，未推送到外部 MQ）
```

**当前限制**：
- `assignWorker` 只在 `mockMode=true` 时启动；生产模式下不做自动分配
- `pushQueue` 内容目前不推送到 WebSocket 下行，需要外部触发

### 1.4 消息调度层（当前未激活）

`SimpleTaskScheduler.scheduleTask(task)` 存在但 `scheduleTasks()` 返回空列表（stub）。  
任务目前不会自动转为 `RUNNING` 状态，需手动调用 API 变更。

## §2 规划架构（未实现）

> 以下为目标设计，**代码中尚未实现**。

### 2.1 Seed 文件上传（规划）

```
POST /api/tasks/{tid}/seeds   ← 接口不存在
  → 流式分批上传 seed 列表
  → 后端写入 seed 表，标记 PENDING
  → 上传完成后标记任务"seed 就绪"
```

### 2.2 大规模 TaskMsg 生成（规划）

```
系统调度服务按 batchSize 从 seed 表取 PENDING 条目
  → 生成 TaskMsg，记录 seedRange
  → 推入 Redis Stream / Kafka 执行队列
  → Gateway 下发给对应设备
```

### 2.3 结果回传（规划）

```
设备执行完毕 → WebSocket 上行结果帧
  → ServerMessageDispatcher 路由到 TaskResultHandler
  → 更新 TaskMsg.status + seed.status
  → Task 进度聚合，全部完成时 → TERMINAL
```
