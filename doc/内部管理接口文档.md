- **路径**：`GET /api/queue/status`
- **实现类**：`QueueController.getQueueStatus()`
- **实测返回**：

```json

  "success": true,
  "data": {
    "inputQueue": 0,
    "outputQueue": 0
```

```json

  "success": true,
  "data": {

    "outputQueueSize": 0,

  }
}
```

- **路径**：`GET /api/session/list`
- **实现类**：`SessionController.listSessions()`
- **返回示例**（有 WebSocket 连接时）：

```json
{
  "success": true,
  "data": [
    {

          "role": "task",
```

## 3. 任务管理 🟢 已实现

基路径：`/status/api/tasks`

| 方法 | 路径 | 功能 | 注意 |
|------|------|------|------|
| `POST` | `/status/api/tasks` | 创建任务 | 初始状态为 `NEW` |
| `GET` | `/status/api/tasks/{taskId}` | 查询任务 + targetList | — |
| `PUT` | `/status/api/tasks/{taskId}` | 更新任务基本信息 | 不含状态变更 |
| `DELETE` | `/status/api/tasks/{taskId}` | 删除任务 | **仅 NEW / TERMINAL 可删** |
| `POST` | `/status/api/tasks/{taskId}/audit` | 审核（approve/reject） | 仅 NEW 可审核 |
| `POST` | `/status/api/tasks/{taskId}/pause` | 暂停 | 仅 READY 可暂停 |
| `POST` | `/status/api/tasks/{taskId}/resume` | 恢复 | 仅 PAUSED 可恢复 |
| `POST` | `/status/api/tasks/{taskId}/terminate` | 终止 | 任意非 TERMINAL 状态 |
| `PUT` | `/status/api/tasks/{taskId}/status` | 直接变更状态 | 通过 status 参数路由 |
| `GET` | `/status/api/tasks/{taskId}/messages` | 分页获取 TaskMsg | `?page=1&size=20` |

### 任务状态机

```
NEW ──approve──► READY ──pause──► PAUSED ──resume──► READY
 │                 │                                    │
 └──reject──► BLOCKED                                   │
 │                                                       │
 └──terminate──────────────────────────────────────► TERMINAL
```

**deleteTask 限制**：只有 `NEW` 和 `TERMINAL` 状态的任务可以删除；其余状态返回 `success=false`。

## 4. WebSocket 消息格式

### 客户端发送（入站）

```json
{
  "msgId": "唯一消息ID",
  "msgType": "PING",
  "subMsgType": "heartbeat",
  "project": "demoApp",
  "context": {
    "deviceId": "设备ID",
    "connRole": "task"
  }
}
```

必填字段：`msgId`、`msgType`、`project`、`context.deviceId`、`context.connRole`

### 服务端错误帧（出站）

当消息解析失败或字段缺失时，服务端返回：

```json
{
  "type": "ERROR",
  "code": "错误码",
  "message": "错误说明"
}
```

| 错误码 | 触发条件 |
|--------|---------|
| `INVALID_FORMAT` | 消息不是合法 JSON 对象 |
| `PARSE_FAILED` | JSON 合法但 context 校验失败 |
| `MISSING_CONTEXT` | context 字段为 null |
| `MISSING_FIELDS` | deviceId/connRole/project/msgId 任一为空 |
| `CHANNEL_ERROR` | Channel 异常（exceptionCaught 触发） |
| `INTERNAL_ERROR` | 服务端未预期异常 |

## 7. 返回格式说明

大多数接口使用 `ApiResponse<T>` 包装：

```json
{
  "success": true | false,
  "message": "说明",
  "data": { ... }
}
```

部分旧接口直接返回 `Map`，格式相同但不经过 `ApiResponse` 包装类。
