## 事件总线与混沌事件体系

### 1. 全局事件总线（EventBus）

- **基础设施**：引入全局唯一的 `xa-mass-eventbus` 模块，基于 Guava AsyncEventBus 实现，支持异步事件分发。
- **统一管理**：所有核心模块（engine、mock、gateway、api等）均可依赖该模块，实现事件的发布与监听。
- **解耦扩展**：事件发布者与监听者完全解耦，便于插拔混沌注入、监控、归因等功能。

### 2. 混沌事件（ChaosEvent）体系

- **事件模型**：所有混沌事件实现 `ChaosEvent` 接口，包含事件类型、严重程度、元数据、描述等。
- **典型事件**：
  - 任务审核类：随机、延迟、部分失败、误通过
  - 设备掉线/上线：批量/单个、闪断、长时间不归队
  - Token/消息异常：失效、反复重试、批量不可用
  - 任务分配冲突、网络异常、监控失效等
- **事件流**：所有事件通过 EventBusManager 统一发布和监听，支持异步处理和全局追踪。

### 3. 事件驱动架构优势

- **高内聚、低耦合**：业务流程通过事件驱动，便于维护和扩展。
- **统一归因与监控**：所有事件自动打点、上报 pipeline，可用于分析和自愈触发。
- **灵活混沌注入**：可定时、概率、条件触发混沌事件，支持可插拔自定义事件生成器。

### 4. 典型用法

```java
// 注册监听器
EventBusManager.register(new TaskReviewListener(...));

// 发布混沌事件
EventBusManager.postChaosEvent(new TaskReviewEvent.TaskReviewRandomEvent(taskId, 1.0));
EventBusManager.postChaosEvent(new DeviceEvent.DeviceOfflineBatchEvent(deviceIds, "网络故障", 5000));
```

### 5. 模块依赖关系

- `xa-mass-eventbus` 只依赖 guava、slf4j 等基础库
- 业务模块依赖 eventbus，实现全局事件驱动
