# 使用 Batch Checks

Status: current Batch Checks user guide.

Batch Checks 将号码或文本种子转换成有限任务，按任务保存的检查契约解释答案。
先读[第一个任务](../first-task.md)，再扩大到自己的输入。

## 普通操作

1. 登录有 `app-checks` Project 授权的身份，打开 `/app-checks`。
2. 点击“创建任务”，先选择“电话号码”或“文本”，再选当前 Catalog 提供的检查能力。
3. 电话号码选择国家并导入 TXT、CSV 或粘贴内容；文本使用 TXT 或粘贴，每行一个种子。
4. 校验通过后创建待审核任务并导入。读取真实数量，必要时继续补充导入。
5. 点击“核对并启动”，核对种子数、执行 Item 数、单价、总额和所有者余额。
6. 手动刷新进度和结果。终态后导出有效答案；中止任务不会自动退款。

普通用户只能管理自己创建的任务；管理员可管理所有任务和检查配置。
管理员代为启动时仍扣 Task 所有者账户。身份或 Project 权限被调整后，
后续请求按 Server 当前目录准入，旧页面可能需要刷新或重新登录。

## 选择能力

| Preview 能力 | 输入与答案 |
| --- | --- |
| App A/B 模拟注册 | 电话号码；注册与未注册是正常答案，也有明确模拟执行失败 |
| 原始运营商识别 | 电话号码；识别号码库中的原始运营商元数据，不是实时在网/携号转网查询 |
| 32 位整数素数判断（演示） | 文本；按该契约校验无符号 32 位整数，再给出素数答案 |
| MD5 前缀命中（演示） | 文本；以实际摘要是否以 `0` 开头判定 |

这只是当前 Preview seed。部署可提供其他已注册的静态契约和检查项。
一个 Group 可以有多项能力；页面声明、Group catalog 与 Worker 已安装 Handler
必须分别核对。

## 数量、错误和导出

一次导入当前限制为 100,000 个去重种子、10 MiB；以 Catalog 和
[导入契约](../../../scenarios/app-checks-jvm/README.md#api-和-task-数据)为准。
`seedsPerItem` 由配置决定并保存在 Task 中，多个种子可以组成一个执行 Item。
计费使用实际持久输入的种子数，不用预览行数推算。

业务答案分为满足和不满足。执行失败、关联不符、协议错误属于检查错误。
结果预览是有界样本；CSV 从完整有效结果流读取，并支持全部、满足、不满足过滤。
没有结果的种子不会被虚构为“不满足”，异常组也不会部分导出成有效答案。

创建或导入出现未知结果时，保留原 requestId、Task ID 和页面回执，先核对原操作。
结束本地草稿不代表取消 Server 上的任务。批准后不可继续导入或重新解释执行绑定；
任务结束也不提供重新打开的入口。

## 管理检查配置

管理员在 `/app-checks?view=configuration` 编辑整份 JSON。保存校验配置结构，
生效需要手动重启；新增检查依赖的 Group、事件、Pool/query 和真实 Worker 需要由
宿主另外准备。保存成功不表示这些依赖已经具备。

现有任务沿用首次创建时保存的执行配置、参数与单价；新配置只作用于后续新任务。
查看[配置归属](../operations/configuration.md)和
[Batch Checks Owner](../../../scenarios/app-checks-jvm/README.md#模块内配置存储)。
