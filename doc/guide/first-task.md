# 完成第一个任务

Status: current real-Worker Batch Checks walkthrough.

本教程用 Preview 的 **MD5 前缀命中（演示）** 检查三个文本。
它会经过真实 Server、Task/Item、Matching、Java Worker 和结果读取。
该演示将“MD5 摘要以 `0` 开头”解释为满足条件，不涉及外部查询。

## 确认环境和余额

先完成[快速启动](quick-start.md)，在真实 Console 登录管理员 `1000`。
保持本教程的创建和启动都使用这个身份，便于核对同一账户。

打开“批量检查”→“创建任务”，选择种子格式“文本”，检查能力
“MD5 前缀命中（演示）”。当前 Preview seed 的 `checkId` 为 `md5-prefix`，
单价为 1 积分/种子、每个 Item 最多包含 10 个种子。实际页面应显示这些生效值；
若不同，先检查是否保留了以前的配置文件，不要直接覆盖仍在使用的环境。

在个人积分页 `/?view=credits` 查看管理员自己的余额。如果不足 3 积分，在该页
“人工调账”选择“增加积分”，输入 `3` 和原因“首次任务演示”，提交后读取确认结果。
管理员可调整自己的积分账户，即使当前登录用户的身份资料不可编辑。
若调账结果未确认，使用原请求核对，不重复创建新调账。

## 创建并导入

选择“粘贴种子”，输入以下三行，不包含代码围栏：

```text
hello
test
a
```

确认校验通过后，点击“创建待审核任务”。页面依次创建空任务并导入种子，
成功后回到列表；此时还没有开始执行。记下 Task ID。

按当前 seed 分组，这三个唯一种子组成 **1 个执行 Item**。
种子数量和 Item 数量是不同口径，费用按实际种子数计算。
如果创建或导入提示未确认，保留页面中的原请求身份和已知 Task ID，先核对，
不要新建相同业务任务来替代恢复。

## 核对费用并启动

在该任务操作菜单中点击“核对并启动”。确认弹窗应显示：

| 项目 | 本教程的期望 |
| --- | --- |
| 检查能力 | MD5 前缀命中（演示） |
| 实际种子数 | 3 |
| 执行 Item 数 | 1 |
| 单价 | 1 积分/种子 |
| 总额 | 3 积分 |
| 余额 | 至少 3 积分 |

点击“确认扣分并启动”，然后按实际状态手动刷新列表或结果预览。若余额不足，先补足余额，再重新读取
数量与金额、明确确认新的启动请求。若已有扣费或启动未确认，使用界面提供的原请求
核对/继续操作；同一个执行任务不会因为普通调度重试而追加扣费。

## 核对答案并导出

这三个输入的 UTF-8 MD5 摘要如下：

| 种子 | 摘要 | 判定 |
| --- | --- | --- |
| `hello` | `5d41402abc4b2a76b9719d911017c592` | 不满足 |
| `test` | `098f6bcd4621d373cade4e832627b4f6` | 满足 |
| `a` | `0cc175b9c0f1b6a831c399e269772661` | 满足 |

在结果抽屉检查三条种子答案和摘要，等任务达到终态后选择“导出结果”，
导出范围选“全部有效成功结果”，点击“生成 CSV 文件”，确认显示 3 条后点击“下载 CSV”。
CSV 应包含三个有效答案，其中满足 2 条、不满足 1 条。预览按种子展开，
不能把 1 个执行 Item 误当成只有 1 条业务答案。

执行失败或协议内容错误属于“检查错误”，不应显示成“不满足”。
创建、扣费、执行和导出成功后，才完成这条闭环；只看到 Worker 连接或 Task ID
不能替代最终答案核对。

## 这条教程依赖什么

生效配置来自 [Preview 检查 seed](../../scenarios/app-checks-jvm/src/main/resources/app-checks/preview-configuration.json)；
Host 通过 [products.json](../../worker_simulator_jvm/config/products.json) 安装
`extension.worker.string.md5.batch`。
种子分组、费用、结果和保存配置的完整规则属于
[Batch Checks Owner](../../scenarios/app-checks-jvm/README.md)。
更大的数据集或其他检查能力从[批量检查使用说明](usage/batch-checks.md)继续。
