# 日志输出规范

## 概述

项目中打印信息统一使用日志框架（SLF4J），严禁使用 `System.out.println`、`System.err.println` 等直接输出方式。

## 日志框架

项目使用 **SLF4J (Simple Logging Facade for Java)** 作为日志门面，具体实现由 Spring Boot 自动配置。

### 依赖

```xml

<dependency>
    <groupId>org.slf4j</groupId>
    <artifactId>slf4j-api</artifactId>
</dependency>
```

## 日志使用规范

### 1. 日志级别

按照重要性从低到高：

- **TRACE**: 最详细的调试信息，通常只在开发时使用
- **DEBUG**: 调试信息，用于开发调试
- **INFO**: 一般信息，记录程序正常运行的重要事件
- **WARN**: 警告信息，表示可能的问题
- **ERROR**: 错误信息，表示程序错误或异常

### 2. 日志使用方式

#### 正确的使用方式

```java
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

public class ExampleService {
    private static final Logger log = LoggerFactory.getLogger(ExampleService.class);

    public void doSomething() {
        log.info("开始执行操作");

        try {
            // 业务逻辑
            log.debug("处理数据: {}", data);

        } catch (Exception e) {
            log.error("操作失败: {}", e.getMessage(), e);
        }

        log.info("操作完成");
    }
}
```

#### 错误的使用方式

```java
// ❌ 严禁使用
System.out.println("开始执行操作");
System.err.

println("操作失败: "+e.getMessage());
        e.

printStackTrace();
```

### 3. 日志格式规范

#### 使用占位符

```java
// ✅ 推荐：使用占位符
log.info("用户 {} 登录成功，IP: {}",userId, ipAddress);
log.

error("处理任务 {} 失败: {}",taskId, e.getMessage(),e);

// ❌ 不推荐：字符串拼接
        log.

info("用户 "+userId +" 登录成功，IP: "+ipAddress);
```

#### 异常处理

```java
// ✅ 推荐：包含异常对象
try{
        // 业务逻辑
        }catch(Exception e){
        log.

error("操作失败: {}",e.getMessage(),e);
        }

// ❌ 不推荐：只记录消息
        try{
        // 业务逻辑
        }catch(
Exception e){
        log.

error("操作失败: "+e.getMessage());
        }
```

### 4. 日志内容规范

#### 信息性日志

```java
// 应用启动/停止
log.info("应用启动成功，端口: {}",port);
log.

info("应用正在关闭...");

// 重要业务操作
log.

info("用户 {} 创建了任务 {}",userId, taskId);
log.

info("设备 {} 上线",deviceId);

// 配置信息
log.

info("加载配置文件: {}",configPath);
log.

info("使用存储类型: {}",storageType);
```

#### 调试日志

```java
// 方法进入/退出
log.debug("进入方法: {}",methodName);
log.

debug("方法 {} 执行完成，耗时: {}ms",methodName, duration);

// 数据处理
log.

debug("处理数据: {}",data);
log.

debug("查询条件: {}",queryCondition);
```

#### 警告日志

```java
// 配置问题
log.warn("未找到配置文件，使用默认配置");
log.

warn("Redis连接失败，切换到内存存储");

// 业务警告
log.

warn("设备 {} 心跳超时",deviceId);
log.

warn("任务 {} 执行时间过长",taskId);
```

#### 错误日志

```java
// 系统错误
log.error("数据库连接失败: {}",e.getMessage(),e);
        log.

error("Redis操作失败: {}",e.getMessage(),e);

// 业务错误
        log.

error("任务 {} 执行失败: {}",taskId, e.getMessage(),e);
        log.

error("设备 {} 分配失败: {}",deviceId, e.getMessage(),e);
```

## 日志配置

### 1. 开发环境配置

在 `application-dev.yml` 中：

```yaml
logging:
  level:
    com.xa.mass: DEBUG
    org.springframework: INFO
    org.hibernate: WARN
  pattern:
    console: "%d{HH:mm:ss.SSS} [%thread] %-5level %logger{36} -- %msg%n"
    file: "%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} -- %msg%n"
```

### 2. 生产环境配置

在 `application-prod.yml` 中：

```yaml
logging:
  level:
    com.xa.mass: INFO
    org.springframework: WARN
    org.hibernate: ERROR
  file:
    name: logs/application.log
  pattern:
    file: "%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} -- %msg%n"
```

## 最佳实践

### 1. 日志级别选择

- **TRACE**: 仅在开发调试时使用
- **DEBUG**: 开发阶段使用，生产环境可关闭
- **INFO**: 记录重要的业务事件
- **WARN**: 记录可能的问题，但不影响程序运行
- **ERROR**: 记录程序错误和异常

### 2. 性能考虑

```java
// ✅ 推荐：使用占位符，避免字符串拼接
log.debug("处理数据: {}",expensiveData);

// ❌ 不推荐：字符串拼接，即使日志级别关闭也会执行
log.

debug("处理数据: "+expensiveData);
```

### 3. 敏感信息处理

```java
// ❌ 不推荐：记录敏感信息
log.info("用户密码: {}",password);
log.

info("Token: {}",token);

// ✅ 推荐：脱敏处理
log.

info("用户 {} 登录",userId);
log.

info("Token: {}",maskToken(token));
```

### 4. 日志轮转

生产环境建议配置日志轮转：

```yaml
logging:
  file:
    name: logs/application.log
    max-size: 100MB
    max-history: 30
```

## 检查工具

可以使用以下命令检查项目中是否还有直接输出：

```bash
# 查找 System.out.println
grep -r "System\.out\.println" src/

# 查找 System.err.println
grep -r "System\.err\.println" src/

# 查找 e.printStackTrace()
grep -r "\.printStackTrace()" src/
```

## 总结

通过统一使用 SLF4J 日志框架，项目获得了以下优势：

1. **统一管理**: 所有日志通过统一的框架管理
2. **级别控制**: 可以根据环境调整日志级别
3. **性能优化**: 使用占位符避免不必要的字符串拼接
4. **格式统一**: 日志格式统一，便于分析和监控
5. **易于维护**: 便于日志收集、分析和问题排查

请所有开发人员严格遵守此规范，确保项目日志的一致性和可维护性。
