# Transport WebSocket Session Registry Convergence Roadmap

Status: completed and archived 2026-06-23.

Archive note: mainline implementation converged WebSocket session state into
`WebSocketSessionRegistry`, removed routeKey-only WebSocket output plumbing,
and removed endpointAddress from endpoint lease/evidence contracts. Current
owner truth is in `transport/WEBSOCKET_ADAPTER_BOUNDARY_BASELINE.md`,
`transport/TRANSPORT_BOUNDARY_BASELINE.md`, and `doc/PROOF_REGISTRY.md`.

## Summary

`WebSocketSessionStore` is currently exposed as a separate public adapter-local
storage object, but it is not an owner boundary. It is an implementation detail
of WebSocket final-hop session lookup and evidence publication.

The current store also carries three concepts as if they were equivalent:

- `workerId`: selected-worker final-hop identity.
- `deliveryBucketId`: currently worker-group context used by endpoint/session
  evidence.
- `endpointAddress`: legacy routeKey/fallback bucket address used by raw/manual
  route side-channel and endpoint evidence metadata.

Target direction:

```text
WebSocket assigned delivery:
  selectedWorkerId -> WebSocket session/channel

WebSocket session lifecycle:
  channel -> worker session

WebSocket evidence:
  workerGroupId + workerId + sessionHandle -> endpoint/session evidence
```

`endpointAddress` should not remain in the WebSocket session lookup/index
mainline. It is not a network address, not an adapter mailbox, and not a
selected-worker delivery identity. The current transport endpoint lease API
still requires this field, so the first WebSocket slice may keep it only as
isolated legacy evidence metadata. It must not be indexed, used for send, or
treated as session identity.

If raw/manual route sending still needs a route-style address, it must be a
separate side-channel roadmap with an explicit owner, not an index inside the
assigned-delivery session registry.

## Current Code Observations

- `WebSocketSessionStore` is a public class constructed in
  `WebSocketTransportAdapterBootstrap` and passed to both
  `WebSocketSessionController` and `WebSocketSessionEvidenceRefresher`.
- `WebSocketSessionStore` currently owns:
  - `recordsByWorkerId`
  - `recordsByChannel`
  - `recordsByEndpointAddress`
  - `retiredChannels`
- Assigned dispatch uses only selected worker lookup:
  `WebSocketTaskDispatchChannel -> WebSocketSessionController.sendTextToWorker`
  -> `WebSocketSessionStore.activeChannelForWorker`.
- `endpointAddress` is generated by `WebSocketSessionOpenFrameReader` from
  frame/query `routeKey`, or falls back to `"bucket:" + workerGroupId`.
- `DispatcherInboundHandler` names `identity.endpointAddress()` as `routeKey`
  before calling `sessionHandle.addSession(workerGroupId, routeKey, workerId,
  channel)`.
- `WebSocketRawWorkerRouteEndpointRegistry` uses
  `sendTextToEndpointAddress(routeKey, message)` and
  `hasEndpointAddress(routeKey)` for raw/manual route side-channel.
- `TransportOutboundMessage(routeKey, rawJson, traceId)` is the routeKey-era
  outbound queue DTO consumed by `WebSocketOutputProcessor`. It is not
  assigned delivery, result ingress, worker evidence, or the workerId raw
  channel.
- `RawWorkerMessageChannel` is different: it sends raw payloads to an already
  selected `workerId`, and the WebSocket implementation calls
  `sendTextToWorker(workerId, rawJson)`. It is not the routeKey registry.
- `AdapterSessionEvidencePublisher` and `TransportEndpointLease*` still accept
  `endpointAddress`. In this path the field is evidence metadata and match
  material, not assigned-delivery correctness.
- `WorkerSessionPresenceEvent.routeKey` is optional and already documented as
  diagnostic metadata in worker-runtime presence, not currentness truth.

## Owner Review

Concrete WebSocket adapter owns protocol sessions, local final-hop lookup,
Netty channel lifecycle, and adapter-local evidence publication.

WebSocket adapter does not own worker grouping, scheduling, selected worker
choice, routeKey minting, adapter mailbox placement, raw/manual product
routing, or endpoint lease storage contracts.

Therefore:

- `workerId` is the only WebSocket assigned-delivery lookup key.
- `channel` is the lifecycle reverse lookup key.
- `workerGroupId` is local session-open evidence context for the current
  endpoint lease contract.
- `endpointAddress` is routeKey residue and must be removed from WebSocket
  session lookup and route-only binding. Until the transport endpoint lease API
  is narrowed, it may remain as isolated legacy evidence metadata only.
- `WebSocketSessionStore` should not be exposed as a bootstrap dependency or
  test fixture. Its maps should become private implementation state of a single
  WebSocket session registry/controller object.
- `WebSocketRawWorkerRouteEndpointRegistry` is routeKey side-channel residue.
- `TransportOutboundMessage` and SDK/starter `outputQueue` configuration are
  routeKey outbound queue residue. They should be deleted with the route-only
  output path instead of being rewritten into another workerId DTO.
- `RawWorkerMessageChannel` is a workerId side-channel and is out of scope for
  deletion in this roadmap.

## Boundary Decision

Replace `WebSocketSessionStore + WebSocketSessionController` with one
adapter-local session registry/controller class. The exact class name can be
chosen during implementation, but the owner role should be clear. Suggested
name:

```java
WebSocketSessionRegistry
```

Target fields:

```java
private final Map<String, SessionEntry> sessionsByWorkerId;
private final Map<Channel, SessionEntry> sessionsByChannel;
private final Set<Channel> replacedChannelsAwaitingInactive;
```

No group-level map:

```java
// forbidden
Map<String, Map<String, Channel>> channelsByWorkerGroupAndWorker;
```

No endpoint/route address map:

```java
// forbidden
recordsByEndpointAddress
sessionsByEndpointAddress
sessionsByRouteKey
```

Target `SessionEntry` shape:

```java
private record SessionEntry(
        String workerGroupId,
        String workerId,
        Channel channel
) {
    String sessionHandle() { ... }
}
```

`workerGroupId` is retained only because the current transport endpoint lease
contract still calls this field `deliveryBucketId`. It must not become a
lookup key inside WebSocket session state.

Final registry/controller surface after Phase 3:

```java
void bind(String workerGroupId, String workerId, Channel channel);
void remove(Channel channel);
String currentWorkerId(Channel channel);
boolean sendTextToWorker(String workerId, String message);
List<SessionSnapshot> activeSessionSnapshots();
void shutdown();
```

This allowlist is intentional. The session registry/controller must not grow
raw route send, route lookup, endpoint diagnostics inventory, worker lifecycle
decisions, adapter health supervision, reconnect/failover, group broadcast, or
task dispatch policy methods.

Phase 1/2 transitional registry input while the endpoint lease API still
requires an endpoint address:

```java
void bind(String workerGroupId,
          String workerId,
          String legacyEvidenceEndpointAddress,
          Channel channel);
```

The third argument is not session identity. It exists only to carry the current
legacy evidence value into `AdapterSessionEvidencePublisher` until Phase 3
removes endpointAddress from endpoint lease contracts. It must be stored only on
the private session entry/snapshot used by evidence publication. It must not
have an index, send method, lookup method, diagnostics inventory, or
assigned-delivery caller.

The session-open reader output can be named to reflect that transitional split:

```java
WebSocketSessionOpenFacts(
        String workerGroupId,
        String workerId,
        String legacyEvidenceEndpointAddress)
```

`WebSocketSessionIdentity` should be reserved for the Phase 3 final shape where
only `workerGroupId + workerId` remain. If the existing class name is kept in
Phase 1/2 for a smaller patch, tests must still assert that the legacy endpoint
value is evidence-only and does not affect session identity.

The assigned-delivery send path remains:

```text
DispatchMessage.selectedWorkerId
  -> WebSocketSessionRegistry.sendTextToWorker(workerId, frame)
  -> sessionsByWorkerId.get(workerId)
  -> channel.writeAndFlush(...)
```

The evidence refresh path becomes:

```text
WebSocketSessionEvidenceRefresher
  -> registry.activeSessionSnapshots()
  -> AdapterSessionEvidencePublisher.heartbeat(
       workerId,
       workerGroupId as current deliveryBucketId,
       legacyEvidenceEndpointAddress, // Phase 1 only; removed in Phase 3
       sessionHandle,
       reason,
       traceId
     )
```

Do not introduce a new synthetic endpoint address from `workerId` or
`workerGroupId`. If the current evidence API still forces a nonblank
endpointAddress before Phase 3, keep the existing legacy value isolated as
evidence debt and remove it in the same slice that narrows the endpoint lease
API. Do not use that value for lookup, routing, or session identity.

## Target Shape

```text
handshake/session-open frame
  -> WebSocketSessionIdentity(workerGroupId, workerId)
  -> Phase 1/2: WebSocketSessionRegistry.bind(
       workerGroupId,
       workerId,
       legacyEvidenceEndpointAddress,
       channel)
  -> Phase 3: WebSocketSessionRegistry.bind(workerGroupId, workerId, channel)
       sessionsByWorkerId[workerId] = entry
       sessionsByChannel[channel] = entry
       replacedChannelsAwaitingInactive handles old channel close races
       publish connected evidence

assigned dispatch
  -> WebSocketTaskDispatchChannel
  -> registry.sendTextToWorker(selectedWorkerId, frame)

channel inactive
  -> registry.remove(channel)
  -> publish disconnected evidence if current

periodic evidence hygiene
  -> WebSocketSessionEvidenceRefresher
  -> registry.activeSessionSnapshots()
  -> publish heartbeat evidence
```

## Non-Goals

- Do not redesign general transport dispatch, result ingress, adapter mailbox,
  or worker-runtime selection.
- Do not introduce group-level WebSocket broadcast or group-indexed session
  lookup.
- Do not preserve raw/manual route send by hiding routeKey under a renamed
  `endpointAddress`.
- Do not delete `RawWorkerMessageChannel` as part of routeKey cleanup. It is a
  workerId side-channel and has a separate owner surface.
- Do not make WebSocket adapter choose workers or infer worker lifecycle.
- Do not rename transport-wide `deliveryBucketId` everywhere in this roadmap.
  WebSocket session code may call the local handshake fact `workerGroupId`,
  while the existing transport endpoint lease API still uses
  `deliveryBucketId`.
- Do not start a broad routeKey removal roadmap here. This roadmap removes the
  WebSocket routeKey-derived `endpointAddress` session path and the routeKey
  outbound queue path (`TransportOutboundMessage` / SDK `outputQueue`) because
  they are the same WebSocket route-only residue. Other routeKey metadata or
  unrelated transport contracts stay out of scope.

## Do Not Start With

Do not start by adding a `groupId -> workerId -> channel` map. That makes
worker group a WebSocket local routing dimension again and recreates the same
boundary problem that routeKey/endpointAddress introduced.

Do not start by renaming `endpointAddress` to `sessionAddress` or
`rawRouteAddress` while keeping the same index. The target is removal from the
WebSocket session mainline, not a better name for the same residue.

Do not start by deleting `deliveryBucketId` from endpoint lease APIs without
first deciding whether this roadmap is executing only the WebSocket slice or
also the transport-wide endpoint lease slice.

Scope:

- Inventory all production and test references to:
  - `WebSocketSessionStore`
  - `recordsByEndpointAddress`
  - `endpointAddress`
  - `sendTextToEndpointAddress`
  - `hasEndpointAddress`
  - `WebSocketRawWorkerRouteEndpointRegistry`
  - `WebSocketOutputProcessor`
  - `TransportOutboundMessage`
  - SDK/starter `outputQueue` and `MessageQueue<TransportOutboundMessage>`
  - `RawWorkerMessageChannel` WebSocket contribution
  - `TransportEndpointLease*` endpointAddress fields
  - `WorkerSessionPresenceEvent.routeKey` assertions in tests
- Classify each hit as:
  - assigned-delivery mainline
  - lifecycle reverse lookup
  - evidence metadata
  - raw/manual route side-channel
  - routeKey outbound queue residue
  - diagnostics/test residue
  - transport-wide endpoint lease contract

Acceptance:

- Inventory proves assigned WebSocket dispatch uses only workerId lookup.
- Inventory proves endpointAddress is routeKey/fallback residue, not a network
  address.
- Inventory distinguishes routeKey raw registry from workerId raw channel:
  `WebSocketRawWorkerRouteEndpointRegistry` is route-only residue;
  `RawWorkerMessageChannel` is selected-worker raw side-channel and is not
  deleted by this roadmap.
- Inventory proves `TransportOutboundMessage` / SDK `outputQueue` is routeKey
  outbound queue residue, not a current assigned-delivery, result-ingress, or
  worker-command contract.

## Phase 1 - Collapse Store And Remove Route-Only Output

Scope:

- Replace public `WebSocketSessionStore` construction with one WebSocket
  session registry/controller object.
- Move store maps and private records into that owner.
- Keep only:
  - workerId -> entry
  - channel -> entry
  - replaced/retired channel de-dup set
- Rename local `deliveryBucketId` parameters on WebSocket session-open path to
  `workerGroupId`.
- Keep current evidence publisher calls compiling by mapping local
  `workerGroupId` into the existing `deliveryBucketId` argument.
- Keep any required `endpointAddress` value as a private
  `legacyEvidenceEndpointAddress` only while the transport endpoint lease API
  still requires it. It must not have an index or send method.
- Update `WebSocketSessionEvidenceRefresher` to read snapshots from the
  registry/controller through a narrow read method.
- Delete `sendTextToEndpointAddress(...)`, `hasEndpointAddress(...)`,
  `recordsByEndpointAddress`, and the WebSocket route-only registry path:
  `WebSocketRawWorkerRouteEndpointRegistry` plus route-only dispatcher wiring.
- Delete or disable the WebSocket routeKey output path in the same slice:
  `WebSocketOutputProcessor`, `TransportOutboundMessage(routeKey)` WebSocket
  processing, and tests that prove `sendToAdapterRoute(...)`. This is the
  route-only side-channel, not workerId raw message delivery.
- Remove route-only dependencies from `WebSocketDispatcherContext` and
  `WebSocketInputProcessorTest`; result ingress input handling must not require
  a `RawWorkerRouteEndpointRegistry` mock after the route-only sender is gone.
- Remove routeKey outbound queue plumbing in the same slice:
  - `TransportOutboundMessage`
  - `TransportConfig.outputQueue`
  - `TransportRuntimeComposition` output queue resolution
  - `MessageTransporter<String, TransportOutboundMessage>` usage that exists
    only to carry the old output queue or report its size
  - builder/SDK examples/tests that configure
    `MessageQueue<TransportOutboundMessage>`
- Update transport queue diagnostics to stop reporting routeKey output queue
  size. `getTransportQueueDetail()` and `TransportQueueDiagnosticsMapper`
  should either report only still-live queue facts or drop the output queue
  fields entirely.
- Delete the route-only API contract if WebSocket was the only production
  owner: `transport_api.RawWorkerRouteEndpointRegistry` must not remain as an
  orphan interface after `WebSocketRawWorkerRouteEndpointRegistry` and
  `WebSocketOutputProcessor` are removed. If Phase 0 discovers a non-WebSocket
  production owner, move that owner to a separate side-channel roadmap before
  removing the WebSocket route index.
- Keep the WebSocket `RawWorkerMessageChannel` contribution because it sends to
  an already selected workerId via `sendTextToWorker(...)`.
- Update tests so they do not instantiate `WebSocketSessionStore` directly.
- Delete or rewrite `WebSocketOutputProcessorTest`; it must not preserve
  `sendToAdapterRoute(...)` or routeKey output as a supported WebSocket path.
- Update the architecture guard and `transport/WEBSOCKET_ADAPTER_BOUNDARY_BASELINE.md`
  in this same slice so proof protects the new shape instead of the deleted
  store.

Acceptance:

- `transport/websocket-adapter` main/test code no longer imports or references
  `WebSocketSessionStore`.
- Session registry contains no `recordsByEndpointAddress` or endpoint/route
  address map.
- WebSocket main code has no `sendTextToEndpointAddress`,
  `hasEndpointAddress`, or `WebSocketRawWorkerRouteEndpointRegistry`.
- WebSocket route-only output processing is removed or explicitly disabled;
  no WebSocket production code calls `sendToAdapterRoute(...)`.
- `WebSocketDispatcherContext` and `WebSocketInputProcessorTest` no longer
  depend on `RawWorkerRouteEndpointRegistry`.
- `TransportOutboundMessage` and SDK/starter routeKey `outputQueue` plumbing no
  longer exist in production code.
- Transport queue diagnostics no longer expose or test routeKey output queue
  size.
- `transport_api` does not expose `RawWorkerRouteEndpointRegistry` after the
  WebSocket route-only implementation is removed, unless Phase 0 documented a
  separate production owner and successor roadmap.
- No test keeps `WebSocketOutputProcessor` as proof of a live routeKey output
  path.
- WebSocket `RawWorkerMessageChannel` still exists and still sends by workerId.
- WebSocket assigned-dispatch tests still prove selected worker lookup:
  `selectedWorkerId -> channel`.
- Replace-channel tests still prove stale channel disconnect cannot release the
  current session.
- Evidence refresher tests still prove heartbeat refresh for active sessions.
- Guard and WebSocket baseline are updated in the same slice.

## Phase 2 - Quarantine RouteKey From Session Identity

Scope:

- Split WebSocket session-open facts into:
  - identity: `workerGroupId + workerId`
  - temporary evidence metadata: `legacyEvidenceEndpointAddress`, only until
    Phase 3 narrows transport endpoint lease.
- Ensure routeKey, fallback bucket strings, or any legacy endpoint address do
  not affect bind identity, replacement, selected-worker send, channel lookup,
  or current-worker reverse lookup.
- Update tests that currently treat `endpointAddress` or `routeKey` as session
  identity. They may assert legacy evidence metadata only while Phase 3 has not
  landed.

Acceptance:

- `transport/websocket-adapter` main code has no WebSocket session lookup by
  `routeKey`.
- RouteKey query/frame fields do not change workerId binding, selected-worker
  send, or replacement behavior.
- Any remaining WebSocket `endpointAddress` symbol is limited to evidence API
  compatibility, not store/index/send method names.
- Assigned delivery and result ingress behavior are unchanged.

## Phase 3 - Narrow Transport Session Evidence Endpoint Address

This phase is transport-wide and should run only after Phase 1/2 have
stabilized the WebSocket local shape. It is part of the same convergence
problem, but it has a wider proof surface.

Scope:

- Remove `endpointAddress` from:
  - `AdapterSessionEvidencePublisher`
  - `TransportEndpointLeasePublisher`
  - `TransportEndpointLeaseClaim`
  - `TransportEndpointLeaseHeartbeat`
  - `TransportEndpointLeaseRelease`
  - `TransportEndpointLeaseMetadata`
  - `TransportEndpointLeaseViewRecord`
  - in-memory and Redis endpoint lease codecs/stores/tests
- Update `WorkerPresenceSessionPublisher` to publish
  `WorkerSessionPresenceEvent.routeKey = null` unless a protocol has a real
  explicit diagnostic route owner.
- Update polling session evidence driver to stop requiring routeKey-like
  endpoint address values for connect/heartbeat/disconnect.
- Change `WebSocketSessionOpenFrameReader` to stop reading `routeKey` for
  session identity or evidence and stop generating `bucket:<workerGroupId>`.
- Change `WebSocketSessionIdentity` to contain only `workerGroupId` and
  `workerId`.
- Change `WebSocketServerSessionHandle.addSession(...)` to accept only:

```java
void addSession(String workerGroupId, String workerId, Channel channel);
```

- Keep endpoint lease currentness keyed by current store identity:

```text
deliveryBucketId + workerId + endpointDriverId + sessionHandle/leaseToken
```

  without endpointAddress matching.

Acceptance:

- No transport endpoint lease model requires or stores `endpointAddress`.
- Stale session token tests still prove old disconnect/heartbeat cannot revoke
  or refresh a newer session.
- Redis endpoint lease encoding and keyspace tests prove the removed field is
  not serialized.
- Worker-runtime presence tests prove routeKey remains diagnostic/nullable and
  does not drive reachability or delivery target selection.
- WebSocket main code has no `endpointAddress` symbol after this phase.
- WebSocket session-open tests prove routeKey query/frame fields are ignored
  or absent for session binding and evidence.

## Phase 4 - Guard And Owner Docs

Scope:

- Phase 1 must already update the WebSocket guard and baseline that currently
  preserve `WebSocketSessionStore`. Phase 4 is final residue hardening, not the

  - WebSocket adapter main must not reference `WebSocketSessionStore`.
  - WebSocket adapter main must not contain `recordsByEndpointAddress`,
    `sendTextToEndpointAddress`, or `hasEndpointAddress`.

  - WebSocket `RawWorkerMessageChannel` must remain workerId based if it
    remains in product scope.
  - WebSocket session registry must not contain a group-indexed map.

  - `transport/WEBSOCKET_ADAPTER_BOUNDARY_BASELINE.md` in Phase 1
  - `transport/TRANSPORT_BOUNDARY_BASELINE.md`
  - `doc/PROOF_REGISTRY.md`

## Roadmap Completion Criteria

- WebSocket session state is owned by one adapter-local registry/controller,
  not by a public store object passed around bootstrap.
- WebSocket assigned delivery is workerId-only from command to channel write.
- WebSocket session registry has no endpointAddress/routeKey index and no
  group-indexed map.
- WebSocket session-open identity is `workerGroupId + workerId`; routeKey does
  not bind or route the session.
- WebSocket route-only raw registry is gone; workerId-based
  `RawWorkerMessageChannel` is not removed by this roadmap.
- `TransportOutboundMessage` and routeKey output queue plumbing are gone from
  production code.
- Endpoint/session evidence no longer requires a routeKey-derived
  endpointAddress value.
- Guards and owner docs prevent endpointAddress or WebSocket store leakage from
  returning.

## Open Decisions

- Whether routeKey-based raw/manual sending has a real product owner after the
  WebSocket route-only registry is removed. If yes, it needs a separate
  side-channel design with explicit caller, route identity, proof, and guard.
  It must not reuse the assigned-delivery session registry.
- Whether the workerId-based `RawWorkerMessageChannel` should later converge
  with worker command delivery. That is a different owner surface and should
  not be handled by routeKey cleanup.
- Whether the transport-wide `deliveryBucketId` name should eventually become
  `workerGroupId` or a neutral scheduling context id. This roadmap only fixes
  WebSocket local naming and session indexing; broad transport field rename is
  deferred.
