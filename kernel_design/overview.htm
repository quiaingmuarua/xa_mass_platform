XA Mass Kernel
机制全景

Task 调度是当前 Kernel 的控制流主线；Worker resource 与 score 保持独立 truth owner，由 Task 驱动的 scheduling 在需要分配和收敛时调用。 新内核把调度拆成三个连续边界： Task Dispatch 完成选择与 claim，Worker Delivery Dispatch 完成投递， Result Routing 让 TaskItem 与 Worker truth 收敛。 Transport 不重新选 Worker，中间证据也不升级为生命周期 owner。

Kernel Mechanism Score、exact CAS、bounded round 与 owner transition 保证机制正确。
Stable TaskType Bundle 外部只选两个场景类型，不拼装 cache、rule owner 与 acquisition flag。
Owner Truth + Evidence Task、Worker、TaskItem 各写自己的 truth；Seed 只携带相关性证据。

01 · Scenario bundles

两类 Task，只决定 Worker 获取模型

TaskType 是稳定场景组合，不表达任务优先级，也不固化关闭策略。 Empty-close 是两类 Task 共用的独立 policy。

TASK_DRIVEN · PRECOMPUTED

同构且稠密的 Item 复用一条 Task 级 Worker rule。提前筛选 Worker 的成本可以被一批 Item 摊薄。

Rule owner TaskDescriptor
Acquisition PRECOMPUTED
Candidate cache enabled
Warmup Pacer participates while suffix = 0
1 Warmup hint读取稳定 Task rule 与 candidate deficit。
2 HOT pool acquisitionscan → exact lease → match。
3 CandidateWorkerCache保存有过期时间的匹配证据。
4 Dispatch recheckconsume → renew/validate → exact Item claim。
共享 empty-close： 只有连续确认完整 ACTIVE Item band 为空，且达到最大 recheck 次数后，才检查 emptyCloseAtMillis。TASK_DRIVEN 默认阈值为 0； ITEM_DRIVEN 默认是创建后三天；任何类型都可显式关闭。

02 · Ordered coordinates

三条 Score 轴，共享结构而不共享业务语义

对外统一传毫秒时间，score 编码完全 opaque。调用方只能保存并原样返回 lease fence， 不能解析 tag、timeSlot 或 suffix。

Task Score

Task 当前处于哪个调度域，以及该 lane 下一次可执行动作的时间。

band + timeSlot + lane-local suffix
PRE_REVIEW
external approval ↓
ADMISSION_VISIBLE
policy admission ↓
RUNNING_VISIBLE
close ↓
TERMINAL (negative)
ADMISSION suffix = priority（0 最高）；RUNNING suffix = 连续 confirmed-empty 次数。

Worker Score

Kernel 对 Worker TaskItem 调度服务能力的权威分类，不是 socket 在线镜像。

polarity × (timeSlot + laneRank + dirty)
HOT_ACQUIRE (positive)
exact lease / release
future hold → due HOT
trusted rejection / reconnect
RECOVERY_RECHECK (negative)
time = 下次 lane 动作；dirty = 旧匹配证据能否继续；一个 WorkerId = 一个执行槽。

TaskItem Score

短周期被动资源的 acquire、claim、预算与最终结果坐标。

tag + timeSlot + remaining budget
ACTIVE
claim: budget - 1
future claim → due retry
cross-tag outcome ↑
FINAL_FAILED → FINAL_SUCCESS
Final tag 只增大；late success 可覆盖 FINAL_FAILED。当前 ResultContext 不携带 Item claim score。

03 · Bounded background rounds

四个 Pacer，各自只编排 owner 操作

Kernel 不创建一个全知调度循环。每轮读取 bounded evidence、调用明确 owner， stale CAS 是正常并发结果。

Loop 观察 动作 绝不负责
TaskRunningActivationPacer due ADMISSION、descriptor、due ACTIVE Item、RUNNING soft limit Task/System policy 后 exact transition 到 RUNNING 预占 Worker、保证全局公平
TaskWorkerAllocationPacer TASK_DRIVEN warmup hints 与 candidate deficit HOT Worker lease、match、CandidateWorkerCache append 修改 Task score、服务 ITEM_DRIVEN
TaskDispatchPacer due RUNNING、TaskItem、candidate acquisition、empty activity exact claim、WorkerCommand append、RUNNING reschedule / empty recheck 执行 Worker、处理结果
ResultRoutingPacer SUCCESS / WORKER_FAILURE / ADAPTER_REJECTION queues 调用 Task 与 Worker 的可替换结果策略 重新选择 Worker、解释业务子码

04 · Ownership cutpoints

三段主线，三个不同责任

关键不是多建接口，而是明确一个 decision 在哪个 cutpoint 已完成。 后续阶段只能消费该决定，不能反向重做。

Task Dispatch

选择具体 Worker，claim 具体 Item，构造 DeliverSeed 与 transport-neutral Worker command，并写入 Adapter 分桶 mailbox。

output = WorkerCommandEnvelope
Worker Delivery Dispatch

Gateway 提供 point poll；单 owner WebSocket Adapter 批量拉取 mailbox、维护 Worker session，并将结果送入 outcome queue。

output = SeedResult
Result Routing

分类 evidence，存储 last-success，并调用 TaskItem / Worker score owner 收敛。

output = owner transitions
TaskDescriptor TaskType、WorkerGroup、rule 与 task config truth。
CandidateWorkerEntry Worker、route snapshot 与 opaque Worker lease evidence。
DeliverSeed WorkerId、delivery item 与 result context；Adapter 不解析。
WorkerCommandEnvelope 只用于出站命令；携带 commandId、TASK_ITEM、executeBeforeMillis 与 opaque DeliverSeed。
SeedResult opaque context、outcome class 和可选业务 payload。
ResultContext Task/Item/Worker correlation 与 opaque Worker lease fence。

05 · Failure convergence

失败不是统一 retry，而是 owner-local 收敛

Adapter、Worker 与 timeout 只产生 evidence。Result Routing 不理解具体业务错误， 只按公开 outcome class 调用策略。

200 · SUCCESS

先写 Task-scoped last-success HASH，再提升 Item 到 FINAL_SUCCESS，最后 exact release Worker lease。

payload 必须存在；无返回值使用 JSON "null"。
1xxx · WORKER_FAILURE

当前默认策略只 exact release Worker，不修改 Item score。Item 等待原 claim 到期后重新可见。

Worker 已开始执行，因此不是 Adapter rejection。
3xxx · ADAPTER_REJECTION

预留给可信的“尚未进入 Worker”证据。当前策略 exact demote Worker 到 recovery，不修改 Item score。

Point polling Worker不能伪造该类别；长连接 Adapter使用batch ingress。
UNKNOWN

Adapter crash、response 丢失、无结果或 destructive consume 后失败。不能伪造结果，也不能快速释放。

Item claim 与 Worker lease expiry 是 correctness fallback。
Deferred： 可信 3xxx 若要快速释放 Item，必须把 opaque Item claim fence 带回 TaskItemScoreBandCore，并新增 exact release primitive。当前 ResultContext 没有该字段。
旧 publisher 通过 deadline check 后发生长暂停

旧写恢复 可能成为最后 mailbox write；deadline 与 score fence 限制影响

06 · Redis topology

当前规模边界来自 owner key，而不是线程数

增加 Pacer 或 HTTP 并发不会拆分 Redis 热键，反而可能增加重复 observation 与 CAS 竞争。 分片必须先明确 owner 和顺序语义。

Owner key 当前分区 天然批量边界 高规模风险
tr:{prefix}:task:score 全局 Task ZSET bounded due window 全局 Task 热键；多 Pacer 不等于分片
wr:{prefix}:score:{workerGroupId} WorkerGroup 同组 score pipeline / CAS 超大 WorkerGroup 形成单键瓶颈
tr:{prefix}:task:{taskId}:* Task Item score、payload、result 单个极热 Task 的吞吐上限
wd:{prefix}:endpoint-manager:{id}:worker-commands Adapter route 稀疏 HASH point / HSCAN destructive prefetch 需要 bounded memory 与 UNKNOWN fallback
rr:{prefix}:seed-results:{class} 三类 outcome per-class bounded consume 全局 class LIST，尚无 pending/ack

07 · Current contract

已闭合机制与刻意延后的生产策略

这份页面只描述当前主线。Deferred work 不得成为兼容分支，也不反向扩大 Kernel owner。

Executable baseline

  • Task admission、RUNNING soft limit 与 priority window
  • TASK_DRIVEN PRECOMPUTED cache/warmup
  • ITEM_DRIVEN TARGETED point/index acquisition
  • TaskItem exact claim 与 shared empty-close
  • 稳定 Worker command、语义化 SeedResult 与 Adapter-partitioned mailbox
  • Java 单 owner WebSocket Adapter、session generation 与 bounded result retry
  • 三类 SeedResult queue 与 owner-local Result Routing

Deferred policy

  • 公平、quota、resource estimate 与 cadence tuning
  • WebSocket Adapter 多实例 ownership、认证与生产 flow-control
  • 受控 Worker route migration 与自动 failover
  • trusted 3xxx Item fast release fence
  • pending/ack、retention、query projection 与分片

Not promised

  • 外部副作用 exactly-once
  • Transport 重新选择 Worker
  • Candidate cache / mailbox 成为 durable lifecycle truth
  • 任意 Task policy 正交组合
  • 用 TaskType 表达任务优先级
  • 旧 Java 主线兼容路径
