5 分钟看懂
新内核全景

新内核不是一个“Task Dispatch 模块”，而是一条由 Task、Worker、TaskItem 三类调度真相共同驱动的闭环： 有界发现、精确占用、证据交付、结果收敛，再回到下一次调度机会。

4个逻辑调度平面
3条独立 Score 轴
2种公开 TaskType
1条调度主线
Task Admission进入 RUNNING
Task Dispatch观察 ACTIVE Item
Worker Acquisition取得精确 lease
Claim + DeliverSeed绑定并发布 mailbox
Worker Delivery执行并返回 SeedResult
Result Routingowner truth 收敛

01 · Panorama

四个平面，共同组成内核

“平面”是逻辑职责，不要求四个独立进程。它们可以共同部署，但不能互相吞并调度真相。

01

Task Score-Band

观察 Task 与系统条件，给出有限的调度进入机会。

回答：哪些 Task 现在可进入调度轮次？
02

Worker Score-Band

维护 Worker serviceability、HOT/RECOVERY 坐标、dirty fence 与精确 lease。

回答：哪些 Worker 此刻可被占用？
03

Assignment Dispatch

在一个有界轮次中组合 Task、Worker 与 TaskItem，生成 DeliverSeed。

回答：这次具体由谁执行哪个 Item？
04

Result Routing

消费 SeedResult，按结果类别委托 TaskItem 与 Worker owner 操作。

回答：证据如何改变下一次调度机会？
HANDOFF BOUNDARY Worker Delivery Dispatch 位于 Assignment 与 Result 之间： 只把已经选定的 Worker/Item 决定交给 Adapter，并把返回值变成 SeedResult。 不是第五个 score owner

02 · Foundations

少量真相，少量证据

核心对象拥有长期真相；中间对象只携带一次调度决定的证据，不发展成新的生命周期 aggregate。

taskId

Task

稳定的调度容器，持有 TaskType、WorkerGroup、配置、生命周期与 intake 语义。

workerGroupId / workerId

Worker

一个 workerId 是一个 scheduler-visible execution slot；并发能力用多个逻辑 WorkerId 表示。

taskId / messageId

TaskItem

从 append 到 finality 的唯一执行单元；claim 不创建 Work 或 Attempt aggregate。

opaque evidence

DeliverSeed / SeedResult

分别携带一次出站执行决定与回程结果证据；它们不是新的 owner truth。

一句话心智模型： kernel core 移动逻辑状态，owner 维护真相，policy 决定映射，transport 只携带证据。
Kernel Mechanism 有界扫描、score 编码、CAS、lease、claim、mailbox 与 evidence routing；保证“怎么安全地做”。
System Policy RUNNING soft limit、优先级、轮次 cadence、空任务 recheck/close、retry 映射；决定“系统希望怎样调”。
TaskType Contract 把真实场景固定成受支持的规则 owner、Worker acquisition 与 cache 组合；避免公开无意义的策略笛卡尔积。

03 · Scenario contracts

两类 Task，差别在 Worker 规则归属

它们不是 batch/RPC、密集/稀疏或高低延迟标签；唯一稳定差异是完整 Worker 规则由谁拥有，以及候选证据能否复用。

TASK_DRIVEN

Task rule · reusable candidates

同一 Task 的 Item 共享完整 Worker allocation rule，因而可以提前缓存并复用 Task 级候选。

Task allocationRule
+ PRECOMPUTED acquisition
+ CandidateWorkerCache / warmup
  • Dispatch 精确复验 candidate lease 与最新 Worker facts。
  • 缓存只是可丢失 evidence，不是 Task 启动资源预占。
  • 没有缓存命中时不暗中切换到 TARGETED 主线。
ITEM_DRIVEN

Item rule · point acquisition

每个 TaskItem 都拥有完整且非空的 Worker allocation rule，Dispatch 根据 Item 逐个定向获取 Worker。

TaskItem allocationRule
+ TARGETED acquisition
+ no candidate cache / warmup
  • 适合 deviceId 等 Item 级目标，但不等同于 RPC。
  • Target source 必须有界，不做全量 Worker 扫描。
  • 仍使用同一 Worker exact lease 与 TaskItem claim 机制。
共同部分： 相同的 Task admission、RUNNING dispatch、空任务 recheck/close、显式关闭、DeliverSeed、SeedResult 与 Result Routing 主线。

04 · Execution cutpoint

Dispatch 是主线中段，不是整个内核

它的价值是把三个 owner 的当前证据组合成一次具体执行；前面有 admission/Worker truth，后面有 delivery/result convergence。

TaskDispatchPacer

发现有限 RUNNING Task；处理空任务 suffix、Task score pacing、mailbox publication 与 round lifecycle。

TaskItemDispatcher

观察一个 Task 的 record-backed ACTIVE Items，获取 Worker、精确 claim Item，并构造 DeliverSeed。

WorkerCandidateAcquirer

按 TaskType 执行 PRECOMPUTED 或 TARGETED acquisition；exact lease 与 matcher 仍由 Worker owner 约束。

发现 Task只扫描有限 RUNNING score candidates。
观察 Item加载 due score 与 canonical record；过期/预算耗尽先 final-fail。
获取 Worker按 TaskType 读取 cache 或做有界 point acquisition。
精确 claim只 claim 已有 Worker 支撑的 Item，预算在此消耗。
构造 Seed绑定 workerId、Item snapshot、opaque ResultContext。
发布 mailbox按 endpointManagerId 分组，best-effort append/replace。
关键顺序： 先获取并验证 Worker，再 claim TaskItem。Worker acquisition 与 Item claim 使用同一 deadline； candidate 或 mailbox 发布失败不创造第二套恢复真相，lease/claim expiry 负责恢复活性。

05 · Scheduling truth

三条 Score 轴，共享机制而不共享语义

每个 scheduling identity 对应一个 ZSET member 和一个有序 score。Score 是调度坐标，不是完整资源对象，也不是资源写锁。

global taskId

Task Score

控制 Task 的 admission、RUNNING visibility、空任务 recheck 与终结方向。

PRE_REVIEW
↓ owner-approved transition
ADMISSION_VISIBLE
↓ policy AND system soft limit
RUNNING_VISIBLE → terminal
workerGroupId / workerId

Worker Score

表达 kernel-authoritative TaskItem serviceability、下一次可行动时间、rank 与 dirty fence。

HOT_ACQUIRE (+)
↕ exact evidence / recovery
RECOVERY_RECHECK (−)
lease time + dirty + lane rank
taskId / messageId

TaskItem Score

拥有 Item 的 due/claim/retry 坐标、剩余预算和单调 final outcome precedence。

ACTIVE (due / claim)
→ expiry / policy / result
FINAL_FAILED
→ late success may improve
FINAL_SUCCESS

06 · External cut and convergence

交付是稀疏 mailbox，结果回到 owner

Scheduling Plane 已经选好 Worker。Delivery 不重新选择，不拥有 finality；Result Routing 也不复制 TaskItem 或 Worker truth。

Worker Delivery Dispatch

Redis 使用每个 endpointManagerId 一张稀疏 HASH mailbox， field 是已选定的 workerId，value 是 DeliverSeed。 

endpointManagerId mailbox
├── worker-001 → DeliverSeed
├── worker-017 → DeliverSeed
└── worker-204 → DeliverSeed

Worker Adapter
  → point-poll workerId or bounded cursor consume
  → check taskItemClaimUntilMillis
  → invoke selected Worker's local eventCode handler
  → append SeedResult

endpointManagerId 是不可变 route snapshot 与 mailbox partition， 不是 Worker matching 输入；eventCode 只选择 Worker 本地 handler。

200 保存 last-success payload → TaskItem FINAL_SUCCESS → Worker exact release。
1xxx 已进入 Worker 但执行失败：释放 Worker；Item 保持 claim，等待到期重试。
3xxx 可信 Adapter 在执行前拒绝：Worker exact demotion 到 RECOVERY_RECHECK；Item 等待 claim 到期。
∅ 没有结果：不猜测失败原因；TaskItem claim 与 Worker lease 自然到期。

07 · Ownership

每个 owner 只维护自己的真相

调度闭环可以跨 owner 编排，但不能通过合并存储、复制状态或让中间队列升级为 lifecycle truth 来“简化”。

Owner / contract 拥有 明确不拥有
TaskScoreBandCore Task score encoding、bounded query、lifecycle direction、terminal score TaskItem、Worker、candidate 与 result truth
TaskRuntime Task descriptor、canonical TaskItem record、last-success payload Task/Item score 与 Worker lease
TaskItemScoreBandCore Item initialization、claim/retry CAS、final outcome precedence Task lifecycle、Worker serviceability 与 transport
Worker runtime / score Worker descriptor、attributes、serviceability、dirty、exact lease Task admission、Item finality 与 delivery result
Candidate / DeliverSeed runtime 有界、可过期、可替换的中间 evidence 任何 Task、Item 或 Worker lifecycle truth
ResultRoutingPacer bounded consume、decode、group、delegate TaskItem/Worker 私有 mutation 与 score encoding

08 · Current boundary

现在已证明什么，仍刻意不做什么

这是 executable-spec 当前边界，不是生产就绪声明。真实 Redis 未运行时，单元测试也不能替代并发与跨进程证明。

已进入 executable baseline

  • Task / Worker / TaskItem 三条 score 轴与 Redis owner primitives
  • Task admission 与 RUNNING soft limit
  • TASK_DRIVEN PRECOMPUTED + cache/warmup
  • ITEM_DRIVEN TARGETED point acquisition
  • TaskItem exact claim、DeliverSeed sparse mailbox
  • Worker Adapter polling、SeedResult 与 Result Routing

后续 policy / production work

  • cadence、优先级、公平性、quota 与 recovery tuning
  • 认证、session、授权与受控 Worker route migration
  • push、pending/ack 与生产 transport policy
  • 主动 recovery、retention、query projection 与 packaging

明确不是当前承诺

  • 外部副作用 exactly-once
  • transport 重新选择 Worker
  • candidate/mailbox 成为 durable lifecycle owner
  • gang scheduling、preemption 或任意策略组合
  • 为旧 Java 主线保留兼容路径
