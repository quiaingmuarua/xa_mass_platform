## Completion Rules

- Every old task-facing port method named by TROM-0 must appear in the Old Port
  Closure Matrix before TROM-1/TROM-2 implementation starts.
- Every matrix row must have exactly one target mechanism or be explicitly
  classified as engine-shell/internal residue.
- Every matrix row must name closure mode, proof, guard, and status.
- Every ECSP temporary exception marked for TROM-0, TROM, or TROM-4 must have a
  target owner/module, proof, guard, and removal/retention decision before the
  relevant TROM slice is complete.
- Every Task Scheduling Input row must classify whether the current symbol is
  engine-only, converted into a narrow task-runtime command value, or removed.
  New task-runtime public ports must not accept engine `Task`,
  `ResolvedTaskSchedulingPolicy`, `TaskRuntimeProfile`, or resolver classes.
- TROM-0 is not complete while this file contains `pending`, `_TBD`, or
  `later classify` in required rows.

## Decisions

- The Old Port Closure Matrix is the source for first-path selection.
  Append-to-claim is the first non-serving proof target:
  append batch -> scheduler-owned backlog discovery -> lane acquire ->
  worker-runtime reservation/admission -> task-runtime claim.
- Production cutover cannot stop at claim. If the migrated path creates new
  active leases for serving traffic, result/retry/finality and active-lease
  repair must be included or delegated to the new task-runtime owner in the same
  serving slice.
- Engine cutover-prep mappers exist for append items, worker reservations,
  policy snapshots, dispatch bindings, result apply commands, progress
  snapshots, and result-finality outcomes. They are not production bridges;
  they only define the engine-side consumption shape needed before old
  append/claim/dispatch/stats/result paths can close.
- `ClaimLeasePolicy.maxItems` is total batch claim capacity. Worker
  reservations are selected-worker/admission evidence and may be reused
  round-robin for multiple claimed items while preserving distinct lease tokens.
- `TaskRuntimeEngineCutoverPreparationTest` composes those mappers with the
  memory task-runtime adapter in test scope. It proves the shape is coherent;
  `EngineConfigTaskRuntimeServingLaneTest` is the starter assembly proof.
- `TaskRuntimeServingLane` is the current engine-side replacement for old
  hot-path ports in the starter-backed memory/Redis `EngineConfig` assembly. It
  exists to prevent broad raw port-set injection into
  `EngineRuntimeKernelConfig`: serving callers move by routing old hot-path
  ports to one lane owner, then disabling/delegating the matching old paths in
  the same slice.
- `TaskRuntimeRepairPort` now includes active-by-task lease candidates so the
  `TaskLeaseMaintenancePort.getActiveLeaseCandidates(taskId)` maintenance path
  can release worker occupancy without reading physical runtime internals or
  old active-lease DTOs.
- First-version append is all accepted or rejected. Classified partial append,
  caller idempotency keys, and heavy half-commit recovery are not first-slice
  goals.
- Append writes ready backlog truth only. Scheduler-owned discovery uses
  task-level dirty/wakeup hints plus bounded recovery; no implementation may
  create one scheduler entry per ready item. Ready backlog length and task shell
  status are separate facts, and append must not rewrite task lane score.
- Lua, Redis transactions, or equivalent CAS belong only on fenced multi-value
  transitions such as claim, result apply, lease repair, gate/epoch changes,
  discard/terminal cleanup, or append variants with idempotency/backlog-cap/meta
  compare-and-write. Plain first append is not a scheduler mutation.
- First-version policy input is narrowed before crossing into task-runtime:
  append admission, scheduler eligibility, claim lease, retry, finality, and
  runtime epoch are command values, not engine `Task` or fat policy objects.
- First-version active-lease repair uses task-level active discoverability plus
  bounded scan. Exact per-lease expiry ordering is a later strategy upgrade.
- Default Redis durability does not claim Redis-node-loss zero data loss. A
  strict profile must name and verify the Redis persistence/replication policy
  it depends on.
- Transport assigned delivery and result finality are evaluated during
  implementation. If deferred, the closure gap must be named and the
  append-to-claim path remains non-serving instead of being hidden behind a
  bridge or compatibility fallback.
- Starter-backed memory/Redis cutover now routes `EngineConfig` command,
  assignment/runtime-ready, lease, result-ingress, result-query, and
  result-repair responsibilities to `TaskRuntimeServingLane` for the selected
  path. Server Boot profile routing now configures memory-local/durable-local
  through the same starter backend and no longer exposes old task work/result
  runtime Spring beans. The starter-backed selected path also disables the old
  `TaskResultRuntime` repair pump instead of leaving a second result lifecycle
  thread alive. Memory-local and Redis polling E2Es plus Redis Node
  polling/WebSocket/Socket black-box tests prove real external worker and
  split-process result paths through the selected serving lane. Trace-observed
  split-process proof and infra-fault edges remain separate evidence gaps.
- Public old-runtime injection has been closed for the selected starter/SDK
  surface: `EngineConfig` no longer exposes public old runtime getters/setters,
  and `MassEngineBuilder`, `MassApplicationBuilder`, and `MassSdk.EngineOptions`
  no longer accept direct `TaskWorkRuntime` / `TaskResultRuntime` injection.
  `EngineConfig` no longer exposes package-private old-runtime fallback handles,
  constructs runnable legacy in-memory fallback truth, or passes disabled
  old-runtime sentinels into `TaskManager`; `TaskManager` now has no old
  work/result runtime fields or fallback helpers, and no-lane runtime entry
  calls fail because `TaskRuntimeServingLane` is required. `TaskFlowLoadModelRunner` no longer constructs a local legacy
  runtime bundle. `TaskManagerLifecycleTest` no longer constructs runnable old
  memory task runtimes, and the old-runtime `EngineExample` class has been
  deleted. Package-private single-item runtime ingress helpers have also been
  removed so new item writes stay behind batch append/admission.
  `TaskRuntimeRecoveryPortTest` no longer uses a fake `readyTaskIds` override
  over old `TaskWorkRuntime`; recovery proof now goes through
  `TaskRuntimeServingLane` scheduler discovery. `TaskKernelLifecycleTest` no
  longer constructs old memory runtimes or calls old runtime getters; kernel
  lifecycle and append-backpressure proof now runs through
  `TaskRuntimeServingLane`. `SimpleTaskDispatchBinderTest` no longer
  constructs old memory runtimes or calls old runtime getters; assignment and
  dispatch binder proof now runs through `TaskRuntimeServingLane`.
  `TaskResultRuntimeConvergenceTest` no longer constructs old memory runtimes,
  calls old runtime getters, or proves staged callback repair candidates; result
  convergence proof now runs through `TaskRuntimeServingLane` finality, retry,
  and lease-repair ports. `TaskResultConcurrencyConvergenceTest` no longer
  constructs old memory runtimes, calls old runtime getters, or depends on old
  work-result DTOs; result race proof now runs through `TaskRuntimeServingLane`.
  Shared `TaskSchedulingTestHarness` users no longer construct old memory
  runtimes, and `TaskRedispatchCompetitionTest` now proves stale expired-lease
  rejection through task-runtime `ResultApplyCommand` instead of old
  `TaskWorkResult`. `TaskIdleClosePolicyBehaviorTest` and
  `TaskResourceReleaseListenerTest` no longer construct old memory runtimes.
  The no-lane `TaskResultService` staging/repair path and local delayed-dispatch
  helper family are deleted. Engine result reads now use task-runtime
  `FinalResultRow` / `FinalResultWindow` directly and are guarded against old
  `TaskResultRuntimeRow` / `TaskResultWindow` DTOs. Starter result ingress now
  preserves optional worker `leaseToken` payload identity and no-ops mismatched
  attempt or lease identity before engine result apply. Manual
  chaos/diagnostic snapshot proof now uses SDK-owned stats, active-lease, and
  final-result snapshots instead of old runtime DTOs, and
  `TestingTaskRuntimeOldPathClosureGuardTest` prevents manual runners from
  reintroducing old task runtime owner APIs. Old runtime API and implementation
  files have been deleted.
- `platform_infra/mass-task-runtime-memory` is a real infra implementation of
  public task-runtime ports, not a semantic-module pure-memory shortcut.
- `TaskRuntimeNonServingAppendToClaimProofTest` proves the isolated new-owner
  path with synthetic selected-worker reservation evidence only. It is not
  production `WorkerSelectionRuntime` integration and does not close the old
  engine path.
- ECSP temporary exceptions are migration inputs, not preservation constraints.
- Module-internal field residue is tolerated only while it does not cross a
  module boundary, become a public contract, or re-open an old owner path.
- ECSP guards remain part of the TROM regression set whenever starter, embedded
  SDK, engine-starter, or approved starter surfaces are touched.
