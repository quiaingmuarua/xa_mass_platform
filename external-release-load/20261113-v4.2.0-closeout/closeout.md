# Release 4.2.0 公网外部验收收尾（2026-11-13）

本轮按用户确认的 **1,000 Worker 公网直连基础验收**结束，不再继续追求更高数量。100 Worker 的既有通过记录只保留为历史证据，已从手动 CI 档位移除，不再提供为新验收入口。原 15k/10k 公网活动没有通过，调查已关闭；它不是后续 Agent 应自动续跑的待办。除非用户提出新的具体要求，不重开负载实验、购买更大 runner 或继续网络定位。

原始分档运行标签仍是 `diagnostic-only / diagnostic-passed`，本次收尾没有将它们改写成 15k 验收通过。Nightly 和发布工具完整模式的默认规模及断言保持；手动 CI 只保留 1,000 基础档和显式的 15,000 完整目标，默认选择 1,000 并保留 `diagnostic-only`。该参数接线只做本地/CI focused 验证，本轮没有新执行小规模 GitHub 公网验收。

每个主档都是十个 Task、每 Task 5,000 Items。执行前后均通过至少三次扫描、至少 60 秒的连接稳定窗口；实际主档连接数分别为 100、1,000，未缺调度身份。结果核对包括准确消息身份、终态成功状态、独立 UTF-8 MD5 和完整导出。这里核对的是既有执行证据，没有重新执行工作量或重算已省略的业务载荷。

同一入口附带的 99、999 Worker case 也各通过 50,000 项；含附带 case 共 **40 个终态 Task、200,000 个已核对结果**，其中主档为 20 个 Task、100,000 项，不能重复相加。计时包括 WAN、批准和终态轮询；预置及完整验证/导出不计入。它不是 Server 最大 TPS、P99 或每个 Worker 都执行过的证明。

GCP 的既有采样显示资源仍有余量：主档期间 Runtime/Nginx/Redis 合计平均 CPU 分别为 **0.879 / 1.773 核（8 核主机）**，最低可用内存约 **9.09 / 9.03 GiB**；未观察到 swap、OOM、Redis eviction 或连接拒绝增量。五秒采样不证明不存在瞬时峰值，也不构成最大容量结论。

两轮都有十秒 TCP connect timeout；到达 GCP 的 SYN 均获得回复，Host 峰值 FD 约 4,000、RSS 不到 0.5 GiB，远低于记录的资源上限。**4,096 是实测累计端口形状，不是查证的官方 quota，也不能等同于当时同时占用数。** 它支持出口/NAT 分配边界这一调查方向，未唯一定位故障组件。

本地物理出口实验中，1,270 个未到 GCP 的 SYN 身份全部有明确物理 WLAN Tx 记录，并通过虚拟侧 TCP timestamp、物理侧 ISN 和 IPv4 ID 交叉核对。与失败请求强关联的候选为 **WSL 七次 SYN、Windows 明确六次物理 Tx**，不是七次全部匹配。[脱敏逐包见证](matched-witness.json)只保留时序、ISN/IP ID 和计数。

**物理 Tx 不证明无线发送成功或 AP/路由器已收包。** PktMon 文本也缺少部分已知成功包；即使头部 EventsLost/BuffersLost 为零，也不能把 Windows 文本缺失直接判为内核丢包。剩余范围包含 WLAN 驱动、无线/AP 和后续公网路径，本轮不再继续拆解。

SSH 隔离路径下的 10,000→9,999 case 虽各验证了 50,000 项，但连接形态和路径已改变，**不计入公网直连验收或上述速率比较**。

已结束运行的 summary 均确认自有进程停止、临时凭据副本移除。通过档的 Task 已终态；失败建连档没有创建已知 Task。有限 Task 仍按原 retention 处理，没有为收尾删除长驻 scope 或清空 Redis。本次证据核对使用既有文件，不重新执行负载。主机外置记录的文字同步按现有操作日志另行登记；文档更新和记录核对不是新的运行验收，也不把历史 cleanup 记录冒充新的在线检查。
