## **二、主要组件详解**

### 1. **任务事件流 (Redis Stream)**

* 存储所有任务的变更事件（如新建、审核、状态切换等）。
* 由任务事件Handle Service 订阅处理。

### 2. **设备事件流 (Redis Stream)**

* 存储所有设备的变更事件（上线、下线、心跳、占用、释放等）。
* 由设备事件Handle Service 订阅处理。

### 3. **任务事件Handle Service**

* 订阅任务事件流，实时维护**可分配任务集合**（Redis Set/ZSet）。
* 支持任务状态机、优先级、批量任务变更等。

### 4. **设备事件Handle Service**

* 订阅设备事件流，实时维护**可用设备集合**（Redis Set/ZSet）。
* 设备上线/心跳/归还时加入，离线/占用时移出。

### 5. **可分配任务 Set / 可用设备 Set**

* Redis Set（或 ZSet）存储“当前可以分配的任务/设备”ID。
* 可根据优先级/地域/策略分多组。

### 6. **分配调度核心服务**

* \*\*单线程/分片线程（推荐）\*\*周期 pop 一个可用设备（SPOP），遍历 available\_tasks set。
* 对每个 task 检查是否符合调度规则（如最小设备数、Token匹配等），**保证分配原子性**。
* 如果分配成功，立刻将 device 标记为占用，更新分配表。
* 如果没有合适的任务，将设备重新放回 available\_device set。

### 7. **设备-任务分配表**

* 可用内存 Map 或 Redis Hash（如 `device_assignments:{deviceId}={taskId}`）。
* 分配时写入，释放时清空，便于唯一性保障和幂等性恢复。

### 8. **任务消息流/回执流**

* 分配成功后，生成任务消息（消息下发/执行/回执）写入 stream/list，供下游消费。
* 支持消息超时重试、失败处理、回调业务等。

### 9. **回调与归还处理器**

* 任务/设备归还、失败回滚、异常恢复通过专用流/队列归还到 available\_device set。

---

## **三、核心分配流程**

1. **设备事件/任务事件异步入队（高并发入口）**
2. **Handle Service 维护 Set 保证最新状态**
3. **调度服务（单/多线程）**

    * `deviceId = SPOP(available_device_set)`
    * 遍历所有 `available_tasks`，调用`ensure_check`验证状态&规则
    * 满足则分配，写入“占用表”，下发消息；不满足则归还到 available\_device\_set
    * 任务满足“可运行”条件则进入 RUNNING，设备直接占用
    * 任务、设备归还事件回流
4. **设备-任务状态变更、归还、失败都通过事件流处理，系统自愈**

---

## **四、并发与原子性保证**

* **Redis Set SPOP/SREM 保证唯一弹出（可用 Lua 保证原子操作）**
* 分配表写入用 Hash/HSET，原子覆盖，无并发隐患
* 回归归还时务必用事件流，不直接写 Set，避免并发冲突

---

## **五、可扩展点**

* 多租户/多地域：Set/ZSet 分片
* 任务优先级：ZSet（score=优先级/时间）
* 复杂规则/策略引擎：支持插件式校验
* 高可用/主备调度：调度服务用主备/分片/分布式锁选主
* 监控与审计：所有流/事件都可落盘分析

## **六、典型核心代码示意**

### 1. **任务/设备事件流入队**

```java
commands.xadd("task_event_stream", Map.of("type","NEW","taskId",taskId, ...));
commands.xadd("device_event_stream", Map.of("type","ONLINE","deviceId",deviceId, ...));
```

### 2. **Handle Service 维护 Set**

```java
// 设备上线
if (event.type.equals("ONLINE")) {
    commands.sadd("available_device_set", event.deviceId);
}
// 设备下线
if (event.type.equals("OFFLINE")) {
    commands.srem("available_device_set", event.deviceId);
}
```

### 3. **调度分配核心**

```java
String deviceId = commands.spop("available_device_set");
for (String taskId : commands.smembers("available_task_set")) {
    // check 任务/设备状态&规则
    if (ensureCheck(taskId, deviceId)) {
        commands.hset("device_assignments", deviceId, taskId);
        // 下发任务消息...
        break;
    }
}
// 没分配出去归还
if (!分配成功) {
    commands.sadd("available_device_set", deviceId);
}
```

## **七、落地部署建议**

* 全部依赖 Redis 可实现，分布式/单机都能快速上线。
* 各模块建议解耦为独立服务，便于扩展和运维。
* 实现难度低，迁移和升级都非常友好。
